# 判讀證據（下結論前）

> 由 repo-template 管理（基礎層），要改請改範本；本 repo 專屬規則寫在 repo 自己的 CLAUDE.md

踩到時輸出全都是「成功」。下結論前先問：**答案相反時，這個輸出會長得不一樣嗎？** 不會，它就不是證據。

- **零結果先跑對照組**：查不到與真的沒有，輸出一模一樣。正對照＝對確定存在的同類對象跑同一條查詢；
  要驗錯誤訊息分不分得出兩種情況，用負對照（確定不存在的目標）。單一 repo 零命中只證明「不在這個 repo」
- **先確認資料是誰回的、有多新**：未 `git fetch` 的工作副本、本機快取的映像都是舊副本，回的是看起來合理的過期答案
- **「全綠」只證明被執行到的分支沒事**：dry-run 不走寫入分支；檢查工具沒掃到檔也是全綠 →
  對帳「交給它幾個」與「它說掃了幾個」
- **測防護要用「應該被擋」的動作**；修完檢查工具，故意造一個該被抓的案例確認它會紅
- **截斷不是盤點**：`head -N`、查詢介面的預設 limit 都在製造假陰性；回傳筆數剛好是整數上限＝截斷訊號
- **「有沒有差異」只能用差異指令回答**（`diff`、`git log A..B`）—— 列清單永遠有輸出；
  檢查指令非零退出時結論是「不知道」，不是換一條來源補位
- 宣告（repo 裡的設定）與實際狀態雙向都不等價；「總量還剩多少」答不了「這一筆放不放得下」
- **加工過的輸出會取代真值**：`jq '.x // "無"'` 把 `false` 也吃成「無」、`cmd | head || echo 無` 的 `||` 永不觸發、
  `awk length` 數的是位元組 → 探索先看原始輸出，標示層是第二步；已有工具在做的量測不要自己拼
- **自動化回報成功 ≠ 操作成功**：摘要可能印的是計畫數，`set -e`、裸 `wait` 會吞掉錯誤 →
  找一條該腳本管不到的證據源交叉比對；反過來，回報失敗也不等於沒生效
- 要證明「改動對既有行為零影響」，對照組是**改動前的自己**：同一份輸入跑新舊兩版，`diff` 必須為空
- 時序資料先確認取樣粒度比要找的波動更細（聚合會把起伏抹平，和「沒有波動」長得一樣）
- `git log -S` 只列「出現次數改變」的 commit，換值不換次數的那筆會漏 → 追值的歷史要逐 commit `git show`
- 改檔前先問它是不是某支腳本的生成物（改了會在下次生成時被靜默蓋回）→ 改源頭
- WebFetch 回的是另一個模型的摘要，可能把語意寫反 → 要當依據的內容抓原文到本機再 `grep`
- **回報給人的「系統輸出」必須是某次工具呼叫的真實回傳**：還在等就說還在等，推測用「預期」語氣、不帶時間戳或狀態碼
